# 内容包格式要求（以当前代码为准）

> 适用版本：仓库当前 `main`（M2 + 界面 v4）。
> 权威实现：`apps/desktop/src/main/pack-*`、`packages/core/src/scenario/{loader,validate,pack-registry,zip}.ts`。
> 设计冻结稿：仓库根 [`内容包规范.md`](../../内容包规范.md)。两者冲突时以**本文件描述的当前实现**为准；
> 差异清单见 §10。

---

## 0. 一句话与最小包

一个内容包 = **一个目录 + `pack.json` + `persona.md`**。

- 想最快跑通：只写 `pack.json` + `persona.md`（+ 可选 `setting.md` / `host.md`），`mode: "freeform"`。
- 想要阶段、部位、意图表、包内波形：再加 `scenario.json`、`phases/<id>.md`、`waveforms/*.json`，
  `mode: "scenario"`。

| | freeform（轻量包） | scenario（完整包） |
|---|---|---|
| 必需文件 | `pack.json`、`persona.md` | 同上 + `scenario.json` |
| 阶段 | 引擎合成单阶段 `scene` | 由 `scenario.phases` 声明 |
| 意图表 | 引擎默认 5 个 | `scenario.feedbackIntents` 覆盖 |
| 部位 | 只有 `whole-body` | `scenario.regions` |
| 适合 | 第一次测试、快速迭代人设 | 需要结构化意图/部位/包内波形 |

> 当前实现提醒：`scenario` 的阶段图能通过校验，但**运行期不会自动推进**（§7.1）。
> 想测试「一局有阶段感」之前，请先确认这一点，或先用 freeform。

## 1. 目录结构与文件规则

```
MyPack/
├── pack.json              # 必需
├── persona.md             # 必需、非空
├── host.md                # 可选；主持节奏/收尾
├── setting.md             # 可选；场景，每回合注入（建议短）
├── corpus.md              # 可选；当前运行期未注入（§7）
├── scenario.json          # scenario 模式必需；freeform 里出现会警告并忽略
├── phases/
│   └── <phaseId>.md       # 可选；仅当前阶段那篇注入
├── waveforms/
│   └── <id>.json          # 可选；包内波形资产（index.json 目前不支持，会警告忽略）
└── assets/                # 可选；png/jpg/webp（当前运行期未使用）
```

硬规则（导入时校验，违反即拒绝）：

| 规则 | 值 |
|---|---|
| 允许的文件后缀 | `.md` `.json` `.png` `.jpg` `.webp`（其他一律拒绝） |
| 目录深度 | ≤ 3 层（路径段数） |
| 文件路径 | 必须是包内 POSIX 相对路径；禁止绝对路径、`..`、`.` 段、反斜杠、控制字符 |
| 单包总大小 | ≤ 50 MiB（解压后） |
| zip 条目数 | ≤ 2048 |
| 编码 | 文本文件 UTF-8 |
| 符号链接/可执行文件 | 不允许（zip 导入与目录扫描都会跳过/拒绝符号链接） |

导入 zip 的细节（`/api/packs/import`）：

- 支持 **store（method 0）** 与 **deflate（method 8）**；加密、ZIP64、其它压缩方式拒绝。
- UTF-8 文件名标志缺失时按 CP437 解码（Windows 压缩工具的坑已处理），每个条目校验 CRC-32。
- 自动忽略 `__MACOSX/`、`.DS_Store`、`Thumbs.db`。
- 如果 zip 里所有文件都在**同一个顶层目录**下（例如 `MyPack/pack.json`），该目录会被自动剥掉；
  只要根目录已经有文件，则不再剥。**推荐直接压缩目录里面的内容**，让 `pack.json` 位于 zip 根。
- 单个 `.md` 导入**未实现**（规范 §6.1 的便捷路径）：请打成 zip 导入。

## 2. `pack.json`（清单）

```json
{
  "id": "rainy-night",
  "name": "雨夜便利店",
  "version": "0.1.0",
  "engine": ">=0.2 <1.0",
  "mode": "freeform",
  "rating": "all",
  "language": "zh-CN",
  "author": "你的名字",
  "homepage": "https://example.com",
  "description": "一句话介绍",
  "tags": ["日常", "温柔"],
  "license": "CC-BY-NC-4.0",
  "boundaries": ["不出现真实伤害或不可逆情节"],
  "aftercare": { "text": "慢慢缓过来。" },
  "history": { "read": true, "lastN": 1, "windowHours": 72 },
  "metaReactions": [
    { "when": { "endReason": ["left_early"] }, "opening": { "tone": "留有余地", "firstIntent": "soothe" } }
  ],
  "requires": ["region", "waveform"]
}
```

| 字段 | 必需 | 类型 / 规则 | 说明 |
|---|---|---|---|
| `id` | ✅ | `^[a-z0-9][a-z0-9-]*$` | 包身份；同一 id 的多版本共存 |
| `name` | ✅ | 非空字符串 | 控制台/注册表展示名 |
| `version` | ✅ | 严格 `x.y.z`（无预发布/构建元数据） | 每次内容改动建议升版本 |
| `engine` | ✅ | semver 范围，必须接受当前 `ENGINE_VERSION`（`0.2.0`） | 支持：精确 `1.2.3`、`>=x.y.z <a.b.c`、`^x.y.z`、`~x.y.z`；不支持 `>`、`<=`、`*`、`||`、预发布 |
| `mode` | ✅ | `freeform` 或 `scenario` | 决定是否必须提供 `scenario.json` |
| `rating` | ✅ | `all` 或 `18+` | 仅标注/过滤，引擎不审核内容 |
| `language` |  | 字符串 | 建议 `zh-CN` |
| `author` / `homepage` / `description` / `license` |  | 字符串 | 展示/归档用 |
| `tags` |  | 字符串数组 | 展示用 |
| `boundaries` | 建议 | 字符串数组 | **硬约束**，注入提示词最前；为空或缺失只警告（全局边界仍生效） |
| `aftercare.text` |  | 非空字符串 | 收尾文案；**当前运行期未消费**（§7） |
| `aftercare.minMinutes` | ❌ | — | 已废弃：出现只警告并忽略；时长改用 `scenario.session.aftercareMin` |
| `history.read` |  | 布尔 | `history` 出现时必需；`true` 才读跨会话账本 |
| `history.windowHours` |  | >0 数字 | 时间窗 |
| `history.lastN` |  | ≥1 整数 | 只取最近 N 条 |
| `metaReactions` |  | 数组 | 每项 `{when:{endReason?:[], aftercare?:bool}, opening:{tone?, firstIntent?}}`；`endReason` 枚举见 §6 |
| `requires` |  | 字符串数组 | M2 只认 `region`、`waveform`；其它能力仅告警忽略 |

校验补充：

- 未知字段**只警告**（前向兼容），不会被拒绝；拼错的关键字段会表现为「必需字段缺失」错误。
- `metaReactions[].opening.firstIntent` 不在 `scenario.feedbackIntents` 里 → 警告（仍注入 tone）。
- `scenario.json` 里再写 `boundaries` / `aftercare` → 警告并忽略，**只认 `pack.json`**。

## 3. 文本文件在运行期怎么被读

当前 M2 是**单次调用**（一次模型请求同时做计划与写作），系统提示按固定顺序拼装：

```
边界（boundaries） → 主持（host） → 人设（persona 全文） → 场景（setting + 当前阶段 note + 当前阶段 goal） → 短提示（开场 brief / 感知）
```

| 文件 | 是否进入提示词 | 说明 |
|---|---|---|
| `boundaries` | ✅ 每次，最前 | 硬约束，最高优先级 |
| `host.md`（或 `scenario.host` 指向的文件） | ✅ 每次，全文 | 支持节奏/收尾要求；缺失或引用不存在 → 用引擎默认 host（仅警告） |
| `persona.md` | ✅ 每次，全文 | 必须非空；建议写 `## 导演摘要` 小节（**当前单调用不单独使用该节**，但缺失会警告，且未来拆分模式依赖它） |
| `setting.md` | ✅ 每次，全文 | 场景；建议控制在几百字，太长会挤占上下文 |
| `phases/<id>.md` | ✅ 仅**当前**阶段 | 缺失 → 空提示 + 警告；阶段不推进时只有起始阶段那篇会一直生效（§7） |
| `corpus.md` | ❌ 当前未注入 | 文件会被加载但运行期没有读取；语料先并入 `setting.md` 或阶段提示 |
| `scenario.opening` / `npcs` / `secrets` | ❌ 当前未注入 | 兼容字段：只校验类型；内容请写进 persona/setting/phases |
| `assets/*` | ❌ 未使用 | 预留头像/主题资源 |

> 不要指望「写进文件就有魔法」：上面 ❌ 的三类字段在 M2 没有对应行为，写了只会增加校验面。

## 4. `scenario.json`

```json
{
  "host": "host.md",
  "session": {
    "plannedMinutes": 30,
    "phaseWindows": [
      { "phase": "arrival", "from": 0.0, "to": 0.25 },
      { "phase": "resolve", "from": 0.7, "to": 1.0 }
    ],
    "aftercareMin": 0
  },
  "regions": [
    { "id": "hands", "label": "手" },
    { "id": "whole-body", "label": "全身" }
  ],
  "phases": [
    { "id": "arrival", "goal": "抵达与安顿", "advanceWhen": "对方愿意留下", "next": ["resolve"] },
    { "id": "resolve", "goal": "收束", "next": [] }
  ],
  "feedbackIntents": [
    {
      "id": "probe-touch",
      "meaning": "短促试探",
      "regions": ["hands"],
      "distribution": "primary",
      "suggest": { "preset": "pulse", "durationSec": 2, "strength": "low" }
    }
  ]
}
```

### 4.1 `session`

| 字段 | 必需 | 规则 |
|---|---|---|
| `plannedMinutes` | ✅ | 必须出现；正数或 `null`（`null` = 开放式） |
| `phaseWindows` | ✅ | 必须出现且为数组；每项 `{phase, from, to}`，`phase` 必须是已声明阶段，`from/to` ∈ [0,1] 且 `from < to` |
| `aftercareMin` | ✅ | ≥0 的数字（分钟）。**当前实现**：以「完成」结束时会先把状态停在 `ending` 这么久再变 `ended`；测试包建议 `0` |

### 4.2 `regions`（叙事部位）

- 数组，每项 `{id, label}`；`id` 为 `^[a-z0-9][a-z0-9-]{0,31}$`，重复即拒绝。
- 意图 `regions` 引用的每个 id **必须在 `regions` 里声明**，否则**拒绝加载**。
- 声明了但当前没有任何设备通道映射到它 → 运行期降级为 `whole-body`（写审计）。
- 连 `whole-body` 都没有通道映射 → 降级到所有在线 level 通道（写审计）。
- 设备→部位的映射在控制台「游玩 → 设备与软上限」里由人设置（每个设备每个通道一个部位下拉，
  词表就是本文件 `regions[].label`；写 `/api/region`）。玩家看到的是 `label`，提交的是稳定 `id`。
- **label 会进入模型提示词**（连同 id）：`已就位部位` 只列当前确实有已连接通道的已声明部位，
  所以 label 请写玩家能看懂的身体部位名（如「手」「肩背」），不要写内部代号或含数字的度量。

### 4.3 `phases`（阶段图）

- 数组，至少 1 个；**声明顺序里的第一个是起始阶段**。
- 每项 `{id, goal, advanceWhen?, next}`；`advanceWhen` 可选字符串；`next` 必须是阶段 id 数组（空 = 终局）。
- 图规则（全部为 error）：`next` 不能引用未知阶段、不能自环、从起始阶段必须可达所有阶段、
  至少一个可达终局、每个可达阶段都必须能走到终局。
- `phases/<id>.md` 缺失只警告（空提示）。

> 运行期限制：阶段图当前**不自动推进**，`phaseWindows` 与 `advanceWhen` 不参与运行（§7）。

### 4.4 `feedbackIntents`（意图表）

- 数组；每项 `{id, meaning, regions?, suggest?, distribution?}`。
- `id` 唯一，`^[a-z0-9][a-z0-9-]*$`；`meaning` 非空。
- `regions` 省略时按 `["whole-body"]` 处理；给了就必须是已声明 region。
- `distribution` 可选 `synced | primary | round-robin`；**省略时按 `synced`**（所有命中通道一起驱动）。
  建议：试探型意图写 `primary`，环境型写 `synced`。
- `suggest` 可选：
  - `preset`：`steady | pulse | wave | random | ramp`
  - `waveform`：包内波形裸 id、`<packId>:<id>`，或引擎内置 `builtin:<id>`
  - `durationSec`：>0；>600 只警告（执行时会被通道上限夹紧）
  - `strength`：`low | med | high`，含义是**人类区间内的相对档位**（low≈40%、med≈70%、high≈100%），
    仍会被人类设置的通道上限夹紧；内容包永远不能提高上限。
- 意图表为空只警告（导演没有菜单）；`scenario` 模式建议至少给 3–5 个。

## 5. 包内波形资产（`waveforms/*.json`）

一个文件一个波形，支持两种写法：

**A. 段落 DSL（推荐，可读、易改）**

```json
{
  "id": "soft-waves",
  "name": "软浪",
  "sensation": "细密潮汐",
  "tags": ["soft", "slow"],
  "loop": true,
  "segments": [
    { "ms": 1200, "freq": 40, "intensity": { "from": 0, "to": 45 }, "curve": "easeIn" },
    { "ms": 800, "freq": { "from": 40, "to": 25 }, "intensity": { "from": 45, "to": 20 } },
    { "ms": 600, "freq": 25, "intensity": { "from": 20, "to": 0 }, "curve": "easeOut" }
  ]
}
```

**B. 16 位十六进制帧（兼容社区格式）**

```json
{ "id": "community", "name": "社区样例", "loop": true,
  "frames": ["0A0A0A0A00000000", "0A0A0A0A64646464"] }
```

规则：

- `id` 可省略（默认取文件名）；允许 `[A-Za-z0-9._-]`，包内唯一。
- `name` 可省略（默认 id）；`sensation` 是给写作读的感觉标签；`tags` 字符串数组；`loop` 布尔（默认 true）。
- **段落 DSL**：`ms` 为 25–60000 的整数；每段 `freq`/`intensity` 可以是数字或 `{from,to}`；
  `curve` ∈ `linear | easeIn | easeOut | step`；总时长必须是 100ms 的整数倍；总帧数 1–600；
  ≤64 段；`freq` 10–240，`intensity` 0–100；至少一个强度 >0。
- **帧格式**：每帧 16 位十六进制（4 个频率字节 + 4 个强度字节）；帧数 1–600；
  频率 10–240、强度 0–100；越界直接拒绝并指出帧号/槽位；至少一个强度 >0。
- `waveforms/index.json` **不支持**（会警告并忽略）：直接放 `waveforms/<name>.json`。
- 引用：`suggest.waveform` 写裸 id 或 `<packId>:<id>`；内置波形用 `builtin:tide` 等。
  引用不存在只警告，运行期回退默认波形，不阻断。
- 运行时波形 id 会加上 `<packId>:` 前缀，避免包之间重名。
- 许可证：包内波形数据由作者负责；不要打包 GPL 社区预设数据。

## 6. 跨会话记忆与收尾

### 6.1 `history` + `metaReactions`

- `history.read: true` 才会读跨会话账本；否则开场完全中性。
- 账本记录每次会话的 `endReason`（`completed | left_early | paused | panic | stop | unexpected_exit`）。
- `metaReactions` 按**最近一条**结束记录匹配（`windowHours`/`lastN` 先过滤），命中后取
  `opening.tone` / `opening.firstIntent` 注入开场 brief；数值强度仍受人类上限夹紧。
- `firstIntent` 不在意图表 → 警告，只注入 tone。

### 6.2 收尾

- `scenario.session.aftercareMin`：完成结束时先停留 `ending` 这么分钟再进入 `ended`；
  测试包建议设 `0`，否则点「结束」后会等满设定时间。
- `pack.aftercare.text`：当前只校验、运行期未消费（§7）；想控制收尾台词，请写进 `persona.md` /
  `phases/resolve.md`，或让模型在收束回合产出结尾。
- freeform 包没有 `aftercareMin` 等待（引擎不注入该配置）。

## 7. 当前实现的边界（务必先读）

以下是**代码现状**，不是设计意图。按这些限制设计测试内容可以少走弯路。

### 7.1 单次调用 + 阶段不推进

- M2 生产路径是**一次模型请求**（`runTurn`）：边界→host→persona→场景（setting+当前阶段 note+goal）
  →**强制的 `world` 段**（本回合可用意图与部位；即使长人设吃满预算也会保留）。该段由宿主生成：
  - `可用意图：id=meaning；…`（本包 `feedbackIntents`，同时作为 `apply_plan` 的运行时枚举）；
  - `可用部位：whole-body=全身…；id=label；…`（本包 `regions`，同样注入 `apply_plan` 的 regions 枚举；
    `whole-body` 恒为第一项，包不声明也会提供）；
  - `已就位部位：…`（当前有已连接通道的部位）。
  因此模型能选对意图 id 与部位 id，**意图表/部位映射是可实际测试的**；未就位部位被选中时执行器
  按 §4.2 的阶梯降级并写审计。
- `scenario.phases` 的当前阶段恒为**第一个声明的阶段**；`advanceTo` 只被单元测试调用，
  host 没有接线。`phaseWindows`、`advanceWhen`、`next` 目前**不参与运行**（只参与校验与图规则）。
- 因此完整包现在可实际测试的是：意图表与部位定点、部位降级、包内波形、开场 brief、
  时间预算（`plannedMinutes` 触发 50%/80%/90% 检查点与强制收束提醒）、结束/收尾流程。
- 想让「阶段感」在提示词里生效，可把阶段性文字直接写进 `setting.md`，或先用 freeform。

### 7.2 尚未接线的内容文件

| 内容 | 现状 |
|---|---|
| `corpus.md` | 加载进 `LoadedPack.corpus`，但没有进入提示词；语料请并入 `setting.md`/`persona.md`/阶段提示 |
| `scenario.opening` / `npcs` / `secrets` | 兼容字段，仅类型校验；不注入提示词 |
| `pack.aftercare.text` | 校验但未消费 |
| `## 导演摘要` | 校验/警告；当前单调用读 persona 全文，暂未单独使用该节 |
| `assets/` | 未使用 |
| `requires` 里除 `region`/`waveform` | 仅警告忽略 |

### 7.3 界面/导入

- 当前控制台 UI **没有内容包导入/卸载/版本切换按钮**；使用 `tools/install-pack.mjs`
  （或 HTTP API `POST /api/packs/import`、`/api/packs/activate`）。
- 导入即激活；`GET /api/packs` 列出已装版本，游玩页下拉只显示有 active 版本的包。
- 单 `.md` 导入未实现；必须 zip（安装脚本会自动打包）。
- 已安装同 `id@version` 再次导入会被拒绝（`already-installed`）；改版本号再装。

### 7.4 安全不变量

- 内容包**没有提高上限的能力**：只能请求强度档位，执行器映射后仍被人类 `ChannelPolicy` 夹紧，
  绝对上限与 `LOCKED` 闩锁不受内容包影响。
- 内容包是数据：不执行脚本、不联网、不读包外路径；Markdown 渲染会消毒。

## 8. 安装 / 版本 / 更新

1. 启动控制台（`start.bat` 或 `start-dev.bat`）。
2. 校验：`校验内容包.bat <目录>` 或 `node --experimental-transform-types tools/validate-pack.mjs <目录>`。
3. 安装：`安装内容包.bat <目录>` 或 `node tools/install-pack.mjs <目录>`。
   - 自动发现 `state/dashboard.json` 的地址与 token；
   - 也可 `--data-dir` / `--url` / `--token` 手动指定；
   - `--list` 查看已安装；`--zip out.zip` 只打包；`--activate id@version` 切换 active。
4. 控制台「游玩」→ 内容包下拉 → 开局。
5. 更新内容：改文件 → 升 `version` → 重新安装（自动激活新版本；旧版本保留可回滚）。
   会话中途不能换包；下一次开局生效。

## 9. 常见错误速查

| 现象 / 规则 | 原因 | 修法 |
|---|---|---|
| `pack.json is required` / `persona.md is required` | 文件不在 zip 根，或压缩了整个外层目录且被误剥 | 直接把**内容包目录里面的文件**压到 zip 根；或确认顶层只有一个目录 |
| `file type is not allowed` | 出现 `.txt`、`.yaml`、`.zip` 等 | 只留 `.md/.json/.png/.jpg/.webp` |
| `manifest.engine` 报错 | 用了 `>`、`<=`、`*`、`||`、预发布 | 改成 `>=0.2 <1.0` 这类支持的写法 |
| `manifest.version` 报错 | 用了 `0.1` 或 `1.0.0-beta` | 严格写 `x.y.z` |
| `scenario.required` | `mode:"scenario"` 但没 `scenario.json` | 补文件，或改回 `freeform` |
| `phases.no-terminal` / `phases.no-exit` / `phases.unreachable` | 阶段图有死路/不可达 | 至少一个 `next:[]`，且每个阶段都能走到它 |
| `intent.region-undeclared` | 意图引用了未声明的 region | 在 `regions` 里声明，或改用 `whole-body` |
| `scenario.session` 报错 | 缺 `plannedMinutes`/`phaseWindows`/`aftercareMin`，或窗口 `from>=to` | 三个字段都写；窗口 `0 ≤ from < to ≤ 1` |
| `phase.note` 警告 | 阶段缺 `phases/<id>.md` | 补文件（或接受空提示） |
| `host file ... does not exist` 警告 | `scenario.host` 指向不存在文件 | 补文件或删掉 `host` 字段 |
| `suggest.waveform ... falls back` 警告 | 引用的波形不存在 | 用包内 id、`builtin:<id>` 或删掉 waveform |
| `waveform.bounds` / `waveform.output` | 频率/强度越界、总时长不是 100ms 倍数、全 0 输出 | 按 §5 边界调整 |
| `already-installed` | 同 id 同版本已装 | 改 `version` 再装 |
| 导入后游玩页看不到 | 包无 active 版本，或控制台列表未刷新 | `install-pack --list` 检查；重新打开游玩视图 |
| 结束要点很久才变「已结束」 | `aftercareMin` 太大 | 测试包设 `aftercareMin: 0` |

## 10. 与冻结设计稿 `内容包规范.md` 的差异

| 设计稿 | 当前实现 |
|---|---|
| 两段式（导演/写作分离）投影 | 生产是单次调用；`## 导演摘要` 暂未单独使用（拆分模式代码存在但未启用） |
| 阶段图推进 + `phaseWindows` 软约束 | 只做声明、加载与校验；运行期不推进、不读窗口 |
| `corpus.md` 按需检索 | 加载但未注入提示词 |
| `setting.md` 按需检索 | 每回合全文注入（注意长度） |
| `opening` / `npcs` / `secrets` 作为写作素材 | 兼容字段，仅类型校验；不注入 |
| `pack.aftercare.text` 默认收尾文案 | 校验但未消费；`aftercareMin` 生效 |
| 单 `.md` 便捷导入 | 未实现；只接受 zip |
| 界面导入/切换/卸载 | 当前 UI 无入口；走脚本/API |
| `waveforms/index.json` | 未定义 schema，会警告并忽略；直接放 `<name>.json` |
| `requires` 各能力 | 只认 `region`、`waveform`，其余警告忽略 |

| id | 含义 | 默认 suggest | distribution |
|---|---|---|---|

### preset 的默认包络

| preset | 最低点/峰值 | 周期 |
|---|---|---|
| `steady` | 100% | 1000ms |
| `pulse` | 35% | 1200ms |
| `wave` | 35% | 4000ms |
| `random` | 35% | 2000ms，抖动 10 |
| `ramp` | 35% | 8000ms |

### 内置波形 id（可用于 `builtin:<id>`）

`probe`、`surge`、`sustain`、`staccato`、`climb`、`breathing`、`tide`。
