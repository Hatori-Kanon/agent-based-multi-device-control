## 0. 一句话与最小包

一个内容包 = **一个目录 + `pack.json` + `persona.md`**。

- 想最快跑通：只写 `pack.json` + `persona.md`（+ 可选 `setting.md` / `host.md`），`mode: "freeform"`。
- 想要阶段、部位、意图表、包内波形：再加 `scenario.json`、`phases/<id>.md`、`waveforms/*.json`，
  `mode: "scenario"`。

| | freeform（轻量包） | scenario（完整包） |
|---|---|---|
| 必需文件 | `pack.json`、`persona.md` | 同上 + `scenario.json` |
| 阶段 | 引擎合成单阶段 `scene` | 由 `scenario.phases` 声明 |
| 意图表 | 引擎默认 5 个 | `scenario.feedbackIntents` 覆盖 |
| 部位 | 引擎提供 `whole-body`；玩家可为通道自由命名 | `scenario.regions`（可选推荐）+ 玩家自由命名 |
| 适合 | 第一次测试、快速迭代人设 | 需要结构化意图/部位/包内波形 |

> 当前实现（2026-11-04 起）：阶段图**由模型请求、引擎校验后推进**（`apply_plan.advanceTo`），
> 会话时间/当前阶段/时间窗会作为提示词事实；`scenario` 包会**整体覆盖**默认意图表，
> 想保留「显式停下」就请自己写 `stop`（§4.4、§7.5）。
> 阶段感测试见 §4.3 / §7.1。

## 1. 目录结构与文件规则

```
MyPack/
├── pack.json              # 必需
├── persona.md             # 必需、非空
├── host.md                # 可选；主持节奏/收尾
├── setting.md             # 可选；场景，每回合注入（建议短）
├── corpus.md              # 可选；当前运行期未注入（§7）
├── scenario.json          # scenario 模式必需；freeform 里出现会警告并忽略
├── phases/
│   └── <phaseId>.md       # 可选；仅当前阶段那篇注入
├── waveforms/
│   └── <id>.json          # 可选；包内波形资产（index.json 目前不支持，会警告忽略）
└── assets/                # 可选；png/jpg/webp（当前运行期未使用）
```

硬规则（导入时校验，违反即拒绝）：

| 规则 | 值 |
|---|---|
| 允许的文件后缀 | `.md` `.json` `.png` `.jpg` `.webp`（大小写不敏感；其他一律拒绝） |
| 目录深度 | ≤ 3 层（路径段数：`a/b/c.md` 可以，`a/b/c/d.md` 拒绝） |
| 文件路径 | 必须是包内 POSIX 相对路径；禁止绝对路径、盘符、`..`、`.` 段、反斜杠、控制字符 |
| 单包总大小 | ≤ 50 MiB（解压后） |
| zip 体积 | ≤ 64 MiB（导入请求体上限） |
| zip 条目数 | ≤ 2048；重复路径直接拒绝 |
| 编码 | 文本文件应为 UTF-8；**运行时不校验**（非法字节会解码成替换字符，建议用 UTF-8 保存） |
| 符号链接/可执行文件 | 不应包含；安装目录扫描会跳过符号链接，但 **zip 导入本身不检查条目属性/可执行位**（后缀白名单才是实际约束） |

导入 zip 的细节（`/api/packs/import`）：

- 支持 **store（method 0）** 与 **deflate（method 8）**；加密、ZIP64、其它压缩方式拒绝。
- UTF-8 文件名标志缺失时按 CP437 解码（Windows 压缩工具的坑已处理），每个条目校验 CRC-32。
- 自动忽略 `__MACOSX/`、`.DS_Store`、`Thumbs.db`。
- 如果 zip 里所有文件都在**同一个顶层目录**下（例如 `MyPack/pack.json`），该目录会被自动剥掉；
  只要根目录已经有文件，则不再剥。**推荐直接压缩目录里面的内容**，让 `pack.json` 位于 zip 根。
- 单个 `.md` 导入**未实现**（规范 §6.1 的便捷路径）：请打成 zip 导入。

## 2. `pack.json`（清单）

```json
{
  "id": "rainy-night",
  "name": "雨夜便利店",
  "version": "0.1.0",
  "engine": ">=0.2 <1.0",
  "mode": "freeform",
  "rating": "all",
  "language": "zh-CN",
  "author": "你的名字",
  "homepage": "https://example.com",
  "description": "一句话介绍",
  "tags": ["日常", "温柔"],
  "license": "CC-BY-NC-4.0",
  "boundaries": ["不出现真实伤害或不可逆情节"],
  "aftercare": { "text": "慢慢缓过来。" },
  "history": { "read": true, "lastN": 1, "windowHours": 72 },
  "metaReactions": [
    { "when": { "endReason": ["left_early"] }, "opening": { "tone": "留有余地", "firstIntent": "soothe" } }
  ],
  "requires": ["region", "waveform"]
}
```

| 字段 | 必需 | 类型 / 规则 | 说明 |
|---|---|---|---|
| `id` | ✅ | `^[a-z0-9][a-z0-9-]*$` | 包身份；同一 id 的多版本共存 |
| `name` | ✅ | 非空字符串 | 控制台/注册表展示名 |
| `version` | ✅ | 严格 `x.y.z`（无预发布/构建元数据） | 每次内容改动建议升版本 |
| `engine` | ✅ | semver 范围，必须接受当前 `ENGINE_VERSION`（`0.2.0`） | 支持：精确 `1.2.3`、`>=x.y.z <a.b.c`、`^x.y.z`、`~x.y.z`；操作数可省 minor/patch（`>=0.2`=`>=0.2.0`；`1.2` 精确等于 `1.2.0`，不是通配）；不支持 `>`、`<=`、`*`、`||`、预发布 |
| `mode` | ✅ | `freeform` 或 `scenario` | 决定是否必须提供 `scenario.json` |
| `rating` | ✅ | `all` 或 `18+` | 仅标注/过滤，引擎不审核内容 |
| `language` |  | 字符串 | 建议 `zh-CN`；仅展示，不进提示词 |
| `author` / `homepage` / `description` / `license` |  | 字符串 | 展示/归档用 |
| `tags` |  | 字符串数组 | 展示用 |
| `boundaries` | 建议 | 字符串数组 | **硬约束**，注入提示词最前且永不截断；缺失或空数组只警告（全局边界仍生效） |
| `aftercare.text` |  | 非空字符串 | 收尾文案；**当前运行期未消费**，也**不存在引擎默认文案**（§7.2）。想控制收尾台词请写进 `persona.md`/`host.md`/阶段提示 |
| `aftercare.minMinutes` | ❌ | — | 已废弃：出现只警告并忽略；时长改用 `scenario.session.aftercareMin` |
| `history.read` |  | 布尔 | `history` 出现时必需；`true` 才读跨会话账本 |
| `history.windowHours` |  | >0 数字 | 时间窗 |
| `history.lastN` |  | ≥1 整数 | 只取最近 N 条 |
| `metaReactions` |  | 数组 | 每项 `{when:{endReason?:[], aftercare?:bool}, opening:{tone?, firstIntent?}}`；`endReason` 枚举见 §6 |
| `requires` |  | 字符串数组 | M2 只认 `region`、`waveform`；其它能力仅告警忽略 |

校验补充：

- 未知字段**只警告**（前向兼容），不会被拒绝；拼错的关键字段会表现为「必需字段缺失」错误。
- `metaReactions[].opening.firstIntent` 只在 **scenario 包**校验：不在 `scenario.feedbackIntents` 里 → 警告
  （仍注入 tone）；freeform 没有意图表，运行期按默认意图表过滤，不在表里只注入 tone。
- `scenario.json` 里再写 `boundaries` / `aftercare` → 警告并忽略，**只认 `pack.json`**。

## 3. 文本文件在运行期怎么被读

当前 M2 是**单次调用**（一次模型请求同时做计划与写作），系统提示按固定顺序拼装（字符预算约 4000，
不是 token）。预算不足时：在**第一个放不下的块**处截断（`scene` 整段丢弃，`host`/`persona` 截尾，
`briefs` 从尾部减少条数），它之后的块不再加入；`boundaries`、`world`、`protocol` 不参与该预算截断。

```
边界（boundaries，永不截断）
 → 主持（host 全文）
 → 人设（persona 全文）
 → 场景（setting 全文 + 当前阶段 note + 当前阶段 goal；超预算整段丢弃）
 → 本回合事实（开场 brief / 感知，叙事化不含数值）
 → 本回合可用（world：可用意图 / 可用部位 / 已就位部位；不受 4000 预算截断、预算外追加，但自身有 600 字符上限）
 → 工具与输出协议（protocol：可用波形清单、narration/工具纪律；永不截断，预算外追加）
```

> 因为 `setting.md` + `persona.md` + `host.md` 共享约 4000 字符预算，**人设别写成小说**：
> 建议 `persona.md` ≤ 2000 字、`setting.md` 几百字、`host.md` 几条规则。顺序是边界→host→persona→scene→briefs：
> 谁先放不下就在谁那里截断，后面的块直接不进提示词（所以 host/persona 写太长会连带丢掉场景和事实块）。

| 文件 | 是否进入提示词 | 说明 |
|---|---|---|
| `boundaries` | ✅ 每次，最前 | 硬约束，最高优先级 |
| `host.md`（或 `scenario.host` 指向的文件） | ✅ 每次，全文 | 支持节奏/收尾要求；`scenario.host` 文件不存在时回退 `host.md`；两者都没有 → 提示词里没有「主持风格」段（**没有引擎默认 host 文本**） |
| `persona.md` | ✅ 每次，全文 | 必须非空；建议写 `## 导演摘要` 小节（**当前单调用不单独使用该节**，但缺失会警告，且未来拆分模式依赖它） |
| `setting.md` | ✅ 每次，全文 | 场景；建议控制在几百字，太长会挤占上下文 |
| `phases/<id>.md` | ✅ 仅**当前**阶段 | 缺失 → 空提示 + 警告；阶段推进后自动切到新阶段那篇（§4.3/§7.1） |
| `corpus.md` | ❌ 当前未注入 | 文件会被加载但运行期没有读取；语料先并入 `setting.md` 或阶段提示 |
| `scenario.opening` / `npcs` / `secrets` | ❌ 当前未注入 | 兼容字段：只校验类型；内容请写进 persona/setting/phases |
| `assets/*` | ❌ 未使用 | 预留头像/主题资源 |

生成的两块（不是文件，见 `packages/core/src/agent/context/world.ts`、`packages/core/src/agent/prompt.ts`）：

- **world 段**：`可用意图：id=meaning；…`（本包 `feedbackIntents`）、`可用部位：whole-body=全身；id=label；…`
  （只列**当前可达**的部位，见 §7.1）、`已就位部位：…`。这些 id 同时是 `apply_plan` 的运行时枚举。
  写入前会去掉 `meaning`/`label` 里的**数字**以及 `;`/`=`，所以不要用「3 档」「70%」这类写法。
- **protocol 段**：`可用波形：<packId>:<id>=name；…` 加单次调用的工具/正文协议。波形的 `id`/`name`
  会进提示词，`tags`/`sensation` **不进**（只用于文件自述）。

> 不要指望「写进文件就有魔法」：上面 ❌ 的三类字段在 M2 没有对应行为，写了只会增加校验面。

## 4. `scenario.json`

```json
{
  "host": "host.md",
  "session": {
    "plannedMinutes": 30,
    "phaseWindows": [
      { "phase": "arrival", "from": 0.0, "to": 0.25 },
      { "phase": "resolve", "from": 0.7, "to": 1.0 }
    ],
    "aftercareMin": 0
  },
  "regions": [
    { "id": "hands", "label": "手" },
    { "id": "whole-body", "label": "全身" }
  ],
  "phases": [
    { "id": "arrival", "goal": "抵达与安顿", "advanceWhen": "对方愿意留下", "next": ["resolve"] },
    { "id": "resolve", "goal": "收束", "next": [] }
  ],
  "feedbackIntents": [
    {
      "id": "probe-touch",
      "meaning": "短促试探",
      "regions": ["hands"],
      "distribution": "primary",
      "suggest": { "preset": "pulse", "durationSec": 2, "strength": "low" }
    },
    {
      "id": "stop",
      "meaning": "停下",
      "regions": ["whole-body"],
      "suggest": { "durationSec": 1, "strength": "low" }
    }
  ]
}
```

### 4.1 `session`

| 字段 | 必需 | 规则 |
|---|---|---|
| `plannedMinutes` | ✅ | 必须出现；正数或 `null`（`null` = 开放式）。**当前运行期不读**：实际时长由大厅输入决定 |
| `phaseWindows` | ✅ | 必须出现且为数组；每项 `{phase, from, to}`，`phase` 必须是已声明阶段，`from/to` ∈ [0,1] 且 `from < to`。**运行时作为提示词事实（阶段时间窗）传给模型；不会自动切阶段**（§4.3/§7.1） |
| `aftercareMin` | ✅ | ≥0 的数字（分钟）。**当前实现**：scenario 包 `end()` 会先把状态停在 `ending` 这么久再变 `ended`（**任意结束原因都等**，UI 点结束固定发 `completed`）；测试包建议 `0` |

### 4.2 `regions`（推荐部位，可选）

- 数组，每项 `{id, label}`；`id` 为 `^[a-z0-9][a-z0-9-]{0,31}$`，重复即拒绝。**整段可省略或为 `[]`**
  （v6 起它只是作者推荐，不是硬词表；但删它时别留下引用它的意图，见下一条）。
- 意图 `regions` 引用的每个 id **必须在本文件 `regions` 里声明**，否则**拒绝加载**
  （`whole-body` 是通配部位、永远合法，无需声明）；意图不写 `regions` 时默认 `whole-body`
  （没有推荐部位时建议省略意图的 `regions`）。
- 声明了但当前没有任何设备通道映射到它 → 运行期降级为 `whole-body`（写审计）；
  连 `whole-body` 都没有通道映射 → 降级到所有在线 level 通道（写审计）。
- 控制台「游玩 → 设备与软上限」里每个设备每个通道是**自由文本部位名**：
  - 玩家输入与本文件 `regions[].label` 或 `id` 完全一致（trim、大小写不敏感）→ 自动提交包内 id，
    保留本包推荐语义；
  - 否则输入本身成为会话部位 key（NFC、中文/空格可用，1–64 个可见字符，不含 `;`/`=`），
    模型同样可以定点；
  - 同名输入视为同一部位；不再有「内容包未声明」错误——自定义部位是合法状态。
- **推荐 label 会进入模型提示词**（连同 id）；写入前会去掉 label 里的数字与 `;`/`=`
  （所以 label 请写玩家能看懂的身体部位名，如「手」「肩背」，不要写内部代号或含数字的度量）。
- **别名（resolver）**：包 region 的 `label` **包含**玩家通道的部位词（且不等于 region id）时，
  模型用包 id 也能落到该玩家通道。所以 label 应尽量包含玩家会输入的词（例如 label「胸口」能接住「胸」）。
- 提示词里的「可用部位」只列**当前可达**的部位：`whole-body` 恒在，其余必须是已连接 level 通道上的
  部位；**没有已标注通道时只剩 `whole-body`**（不会回退到完整包词表，见 §7.1）。作者推荐了但玩家没标注的
  region 不会出现在菜单里；模型若仍用它，执行器按上面的阶梯降级。
- 省略 `regions`（或写 `[]`）**本身**不会拒绝加载，只给一条 warning；但如果还有意图引用被删掉的
  region id，会以 `intent.region-undeclared` 拒绝加载——请同时删掉/改写意图的 `regions`（或改用 `whole-body`）。

### 4.3 `phases`（阶段图）

- 数组，至少 1 个；**声明顺序里的第一个是起始阶段**。
- 每项 `{id, goal, advanceWhen?, next}`；`advanceWhen` 可选字符串；`next` 必须是阶段 id 数组（空 = 终局）。
- 图规则（全部为 error）：`next` 不能引用未知阶段、不能自环、从起始阶段必须可达所有阶段、
  至少一个可达终局、每个可达阶段都必须能走到终局。
- `phases/<id>.md` 缺失只警告（空提示）。

> 运行期（2026-11-04 起）：阶段推进是**模型请求 + 引擎校验**——模型在 `apply_plan` 里给 `advanceTo`
> （只能取当前阶段的 `next`），引擎校验后推进并写审计 `phase_advance`；非法值被忽略并审计拒绝。
> 提示词每回合会带上**会话时间**（已进行/计划/百分比/剩余）、**当前阶段**（goal、`advanceWhen`）、
> **可推进阶段**和**阶段时间窗**；`phaseWindows` 只作时间参考，**不会自动切阶段**。
> `phases/<id>.md` 仍只注入当前阶段那篇，但阶段推进后会自动切换到下一阶段的提示。
> **新会话重置**：**所有新会话都从第一个阶段开始**（正常结束、暂停或崩溃未完成都一样）；未完成/崩溃的快照
> 仍保留在会话快照与账本（`unexpected_exit`）里，供内容包后续的“特殊阶段”逻辑使用，但 host 不恢复阶段。

### 4.4 `feedbackIntents`（意图表）

- 数组；每项 `{id, meaning, regions?, suggest?, distribution?}`。
- `id` 唯一，`^[a-z0-9][a-z0-9-]*$`；`meaning` 非空。
- `regions` 省略时按 `["whole-body"]` 处理；给了就必须是已声明 region（`whole-body` 例外，永远合法）。
- `distribution` 可选 `synced | primary | round-robin`；**省略时按 `synced`**（所有命中通道一起驱动）。
  建议：试探型意图写 `primary`，环境型写 `synced`。
- `suggest` 可选：
  - `preset`：`steady | pulse | wave | random | ramp`
  - `waveform`：包内波形裸 id、`<packId>:<id>`，或引擎内置 `builtin:<id>`
  - `durationSec`：>0；>600 只警告（执行时会被通道上限夹紧）
  - `strength`：`low | med | high`（换算 **25/50/80%**，相对玩家软区间）。**当前只校验、运行期未消费**：
    `apply_plan` 的 `beats[].strength` 是必填值并覆盖它；实际强度由模型当回合给档位或 `targetPercent` 决定（见 §7.5）。
- 意图表为空只警告（导演没有菜单）；`scenario` 模式建议至少给 3–5 个，且**请包含 `stop`**
  （这不是校验规则，但缺了模型就没有「显式停止」的菜单项）。
- **`scenario` 包会整体覆盖引擎默认意图表**：默认的 `probe-touch` / `ambient-field` / `escalate-step` /
  `soothe` / `stop` 不再存在。要保留「显式停下」，必须自己提供 **id 为 `stop`** 的意图——解析器只按这个 id
  特殊处理（发出 percent 0），改名成 `pause` / `halt` 都不会被识别。
- `metaReactions[].opening.firstIntent` 只能引用你意图表里的 id（否则只注入 tone）。
- `meaning` / `label` 进提示词前会去掉数字与 `;` / `=`，别用数值描述档位。
- 运行期还会附加：一回合每通道只保留一条命令、未提及通道默认延续、同通道 loop 只能最后一拍（§7.5）。

## 5. 包内波形资产（`waveforms/*.json`）

一个文件一个波形，支持两种写法：

**A. 段落 DSL（推荐，可读、易改）**

```json
{
  "id": "soft-waves",
  "name": "软浪",
  "sensation": "细密潮汐",
  "tags": ["soft", "slow"],
  "loop": true,
  "segments": [
    { "ms": 1200, "freq": 40, "intensity": { "from": 0, "to": 45 }, "curve": "easeIn" },
    { "ms": 800, "freq": { "from": 40, "to": 25 }, "intensity": { "from": 45, "to": 20 } },
    { "ms": 600, "freq": 25, "intensity": { "from": 20, "to": 0 }, "curve": "easeOut" }
  ]
}
```

**B. 16 位十六进制帧（兼容社区格式）**

```json
{ "id": "community", "name": "社区样例", "loop": true,
  "frames": ["0A0A0A0A00000000", "0A0A0A0A64646464"] }
```

规则（按当前 loader 实际行为）：

- `id` 可省略（默认取文件名去掉 `.json`）；必须匹配 `[A-Za-z0-9][A-Za-z0-9._-]*`（首字符是字母/数字，
  不能含 `:`），包内唯一；重复 id 拒绝。
- `name` 可省略（默认 id）：`segments` 写法要求 1–64 字符；`frames` 写法不检查长度。
- `tags` 字符串数组：`segments` 写法最多 8 个、每个 ≤24 字符（超限拒绝）；`frames` 写法不检查。
- `sensation` 只是**感觉标签**：loader 会把它追加成一个 tag（所以 `tags` 已有 8 个时再写 `sensation`
  会让 segments 包校验失败）；它**不进提示词**，写作只看到波形 `id` / `name`。
- **波形帧的 `intensity` 是脉宽/纹理，不是整体幅度**：整体幅度由 `beats[].strength` 或
  `change.targetPercent` 决定（两者是正交参数，软件不做乘法）；Coyote 的波形 `intensity` 还会被内部
  `maxWaveIntensity`（默认 80）夹紧。调波形 `intensity` 主要是改变触感纹理，对"强弱"的影响远小于
  强度和频率。
- `loop` 布尔（默认 true，非布尔值静默按 true）：`loop:true` 的波形不仅循环帧，还会在下一 plan/stop 前
  **持续播放**（引擎把短 `durationSec` 抬到 `min(60s, 通道 maxDurationSec)`），适合呼吸/爬行等持续纹理；
  一次性短促纹理（burst/stinger）请写 `"loop": false`，保持你声明的时长。
- **段落 DSL**：`ms` 为 25–60000 的整数；每段 `freq`/`intensity` 可以是数字或 `{from,to}`；
  `curve` ∈ `linear | easeIn | easeOut | step`（默认 `linear`）；总时长必须是 100ms 的整数倍；
  总帧数 1–600（即 100ms–60s）；≤64 段；`freq` 10–240，`intensity` 0–100；至少一个强度 >0。
- **帧格式**：每帧恰好 16 位十六进制（8 个字节：4 个频率 + 4 个强度）；帧数 1–600；
  频率 10–240、强度 0–100；越界直接拒绝并指出帧号/槽位；至少一个强度 >0。
- 同时写 `frames` 和 `segments` 时 **`frames` 优先**，`segments` 被静默忽略。
- `waveforms/index.json` **不支持**（会警告并忽略）：直接放 `waveforms/<name>.json`；
  文件名后缀必须是小写 `.json`（`X.JSON` 会被**静默忽略**，连警告都没有）。
- 未知字段（例如 `license`）**一律静默忽略**：loader 不校验、不读取；许可证信息请写在 `pack.json` / README。
- 引用：`suggest.waveform` 写裸 id、`<packId>:<id>` 或 `builtin:<id>`。不可解析只警告，运行期回退
  **包内按路径排序的第一个波形**（没有默认波形才退化为 plain pattern），不阻断。
  注意：plain pattern 不会主动清掉该通道上一回合已选的波形（会继续沿用）；Coyote 在没有波形时使用固定
  plain 帧（freq 40 / intensity 60，且受 `maxWaveIntensity` 夹紧），并不是"强度单独裸输出"。
  裸写内置名（如 `tide`）运行期能命中内置波形，但**导入期仍会 warning**；引用引擎内置波形时
  建议统一写 `builtin:` 前缀（包内波形则写裸 id 或 `<packId>:<id>`，不要加 `builtin:`）。
- 运行时波形 id 会加上 `<packId>:` 前缀，避免包之间重名。
- 包内波形数据由作者负责；不要打包 GPL 社区预设数据。

## 6. 跨会话记忆与收尾

### 6.1 `history` + `metaReactions`

- `history.read: true` 才会读跨会话账本；否则开场完全中性。
- 账本记录每次会话的 `endReason`（`completed | left_early | paused | panic | stop | unexpected_exit`）。
- `metaReactions` 从**最近一条**结束记录向前找，命中第一条匹配的规则（`windowHours`/`lastN` 先过滤）；命中后取
  `opening.tone` / `opening.firstIntent` 注入开场 brief；数值强度仍受人类上限夹紧。
- `firstIntent` 只在 scenario 包校验（不在意图表 → 警告，只注入 tone）；freeform 没有意图表，
  运行期按默认意图表过滤，不在表里只注入 tone。
- 注意（当前实现）：匹配历史时**不按内容包隔离**，账本里若有别的包留下的结束记录也可能命中本包
  `metaReactions`；包内无法声明"只看本包历史"，不想被影响时请慎用 `history.read` / 宽泛的 `when`。

### 6.2 收尾

- `scenario.session.aftercareMin`：`end()` 会先停留 `ending` 这么分钟再进入 `ended`（**任意结束原因都等**；
  UI 点「结束」固定发 `completed`）。测试包建议设 `0`，否则点「结束」后会等满设定时间。
- `pack.aftercare.text`：当前只校验、运行期未消费，**也没有「引擎默认文案」**（设计稿口径未实现）；
  想控制收尾台词，请写进 `persona.md` / `host.md` / `phases/resolve.md`，或让模型在收束回合产出结尾。
- freeform 包不等待：引擎不会给 freeform 的结束加 `aftercareMin` 停留。

## 7. 当前实现的边界（务必先读）

以下是**代码现状**，不是设计意图。按这些限制设计测试内容可以少走弯路。

### 7.1 单次调用 + 阶段推进（2026-11-04 起）

- M2 生产路径是**一次模型请求**（`runTurn`）：边界→host→persona→场景（setting+当前阶段 note+goal）
  →**强制的 `world` 段**→**强制的 `protocol` 段**。`world`/`protocol` 即使长人设吃满预算也会保留。
  系统提示预算约 4000 字符（不是 token）；预算不足时在第一个放不下的块处截断（`scene` 整段丢弃、
  `host`/`persona` 截尾、`briefs` 减少尾部条数），其后的块不再加入；`boundaries`/`world`/`protocol` 例外。
- `world` 段由宿主生成（`packages/core/src/agent/context/world.ts`）：
  - `可用意图：id=meaning；…`（本包 `feedbackIntents`，同时是 `apply_plan` 的运行时枚举）；
  - `可用部位：whole-body=全身（作用于全部通道）；id=label；…`——**只列当前可达的部位**：
    只有已连接（ready）level 通道上标注过的部位才会出现；`whole-body` 恒为第一项、包不声明也提供。
    **没有已标注通道时只剩 `whole-body`**，不会回退完整包词表。
  - `已就位部位：…`（当前确实有已连接通道的部位；没有则提示用 `whole-body`）。
  `world` 段自身还有 600 字符预算：超了先整行丢掉「已就位部位」，再码点截断剩余文本。
  因此模型能选对意图 id 与部位 id，**意图表/部位映射是可实际测试的**；未就位部位若被选中，执行器
  按 §4.2 的阶梯降级并写审计。
- **阶段推进已经接线**：模型可以在 `apply_plan` 里给 `advanceTo`（目标必须是当前阶段 `next` 里的 id）；
  host 校验通过后调用 `PhaseMachine.advanceTo` 并写审计 `phase_advance`（`ok` / `rejected`）。非法目标
  不会改变阶段，只记一条 `rejected` 审计。**会话恢复不恢复阶段**：所有新会话都从第一个阶段开始；
  未完成快照只保留为会话快照/账本事实（`recovered`/`unexpected_exit`），供内容包后续逻辑使用。
- 每回合提示词都会注入阶段事实（协议段，不受 4000 字预算截断）：
  - **会话时间**：已进行 / 计划 / 百分比 / 剩余；到 90% 会提示"本回合必须收束"；
  - **当前阶段**：`id（goal）`、`advanceWhen`、可推进的 `next`；终局阶段明确写"不可再推进"；
  - **阶段时间窗**：`phaseWindows` 的百分比区间，只作节奏参考，**不自动切阶段**；
  - 有可推进阶段时会提示用 `advanceTo`，且阶段切换由引擎执行、不要只在 narration 里宣称。
- 因此完整包现在可实际测试：意图表与部位定点、部位降级、别名命中、包内波形、开场 brief、
  **阶段推进与阶段提示切换**、时间预算（由**大厅输入的时长**触发 50%/80%/90% 检查点与强制收束提醒；
  `session.plannedMinutes` 不参与实际时长）、结束/收尾流程。
- 阶段感建议：把每个阶段真正的写作差异写进各自的 `phases/<id>.md`；`advanceWhen` 写成模型能理解的自然语言条件，
  模型会结合会话时间与阶段时间窗判断是否给 `advanceTo`。

### 7.3 界面/导入

- 游玩页「开局」卡有「导入内容包」按钮（zip 直传、导入即激活）；也可用
  `tools/install-pack.mjs` 或 HTTP API（`POST /api/packs/import`、`/api/packs/activate`）。
- 控制台没有卸载/版本切换按钮。版本切换用 `install-pack --activate id@version` 或
  `POST /api/packs/activate`；**卸载当前没有任何入口**（UI / HTTP / CLI 都没有，`PackRegistry.uninstall` 未接线）。
- 导入即激活；`GET /api/packs` 列出全部已装版本，游玩页下拉会列出每个包，没有 active 版本的包
  显示为「（无 active 版本）」且不可选。
- 单 `.md` 导入未实现；必须 zip（安装脚本会自动打包）。
- 同 `id@version` 重复导入不会报错：会把 zip 覆盖安装到同一目录
  `content/packs/<id>/<version>/`（同名文件覆盖，新包里没有的旧文件会被清理），
  并重新激活该版本。校验/zip 解析失败不会动已安装的版本；写盘阶段失败时可能已
  覆盖部分同名文件（旧字节无法恢复），重新导入一次即可修复。
- 覆盖安装只影响下一个会话：进行中的会话仍用它启动时加载到内存的包。

### 7.4 安全不变量

- 内容包**没有提高上限的能力**：只能请求强度档位，执行器映射后仍被人类 `ChannelPolicy` 夹紧，
  绝对上限与 `LOCKED` 闩锁不受内容包影响。
- 内容包是数据：不执行脚本、不联网、不读包外路径；Markdown 渲染会消毒。

### 7.5 作者必须知道的运行时约束（v12/v13，2026-11-03）

1. **一回合每通道最多一条真实命令**：同一 `(device, channel)` 的多条 beat 会在解析期合并（最终 body
   取最后一条，`durationSec` 取非 stop 命令的最大值），被合并的写 `superseded` 审计。需要「连续两下」
   请拆到下一回合，不要在一个意图里塞多个 beat。
2. **同通道 loop 只能最后一拍**：被合并掉的前序 loop 命令会记 warning（**最终命令是 `stop` 时除外**，
   loop → stop 是合法收尾）；`loop:true` 的波形只应用在「持续纹理」的最后一条 beat 上，一次性短纹理用 `loop:false`。
3. **未提及的通道默认延续**：上一回合的输出会在下一回合重放（同一 envelope/波形，受通道上限夹紧）；
   **不再刺激某个部位时必须用 `stop` 意图显式停止**——这就是 §4.4 要求意图表必须带 `stop` 的原因。
4. **强度是区间百分比**：模型只看到 0–100 的区间请求（100 = 玩家设定的上限），看不到上限数值。
   `beats[].strength` 的 low/med/high 只是**默认换算** 25/50/80%；level 动作还可以带
   `change.targetPercent`（0–100 连续，优先级最高）和 `change.deltaPercent`（±20 微调），
   因此模型不是只有三档。波形动作的幅度仍只由 `strength` 决定（waveform change 不接受这两个字段）。
   所有值最终都被人类上限夹紧，内容包无法提高上限。提示词**不规定**“普通强度”区间：模型按情境自行选择
   （轻微刺激可以用很小的 `targetPercent`），实际输出由人类的软下限/软上限决定。
   **80% 以上属于剧本玩法层面的“越线”**：引擎不做惩罚、也不会降低人类上限；想让角色在玩家越线/持续反抗时
   做出惩罚性反应，请写进 `persona.md` / `host.md` / `phases/*.md`（这纯粹是玩法内容，不是安全机制）。
5. **正文卫生**：模型输出会被清洗掉工具调用脚手架（DSML/invoke/parameter 等）；作者不需要在 persona 里
   重复这些约束，也不应把它们写进内容。

## 8. 安装 / 版本 / 更新

1. 启动控制台（`start.bat` 或 `start-dev.bat`）。
2. 校验（在**本制作包目录** `deliverables/content-pack-kit/` 内执行；若在仓库根执行，把下面的 `tools/`

   `node --experimental-transform-types tools/validate-pack.mjs <目录>`。需要 Node ≥ 22.19。
3. 安装：`安装内容包.bat <目录>`，或 `node tools/install-pack.mjs <目录>`（需要控制台在运行，或给
   `--url`/`--token`）。只打包不上传：`node tools/install-pack.mjs <目录> --zip out.zip`（不需要控制台）。
   - 自动发现 `state/dashboard.json` 的地址与 token；
   - 也可 `--data-dir` / `--url` / `--token` 手动指定；

4. 控制台「游玩」→ 内容包下拉 → 开局。
5. 更新内容：改文件 → 重新安装（同 `id@version` 会覆盖安装并重新激活；想保留旧版可升
   `version` 再装，旧版本保留可回滚）。会话中途不能换包；下一次开局生效。

## 9. 常见错误速查

| 现象 / 规则 | 原因 | 修法 |
|---|---|---|
| `pack.json is required` / `persona.md is required` | 文件不在 zip 根，或压缩了整个外层目录且被误剥 | 直接把**内容包目录里面的文件**压到 zip 根；或确认顶层只有一个目录 |
| `file type is not allowed` | 出现 `.txt`、`.yaml`、`.zip` 等 | 只留 `.md/.json/.png/.jpg/.webp` |
| `manifest.engine` 报错 | 用了 `>`、`<=`、`*`、`||`、预发布 | 改成 `>=0.2 <1.0` 这类支持的写法 |
| `manifest.version` 报错 | 用了 `0.1` 或 `1.0.0-beta` | 严格写 `x.y.z` |
| `scenario.required` | `mode:"scenario"` 但没 `scenario.json` | 补文件，或改回 `freeform` |
| `phases.no-terminal` / `phases.no-exit` / `phases.unreachable` | 阶段图有死路/不可达 | 至少一个 `next:[]`，且每个阶段都能走到它 |
| `intent.region-undeclared` | 意图引用了未声明的 region | 在 `regions` 里声明，或改用 `whole-body` |
| `scenario.session` 报错 | 缺 `plannedMinutes`/`phaseWindows`/`aftercareMin`，或窗口 `from>=to` | 三个字段都写；窗口 `0 ≤ from < to ≤ 1` |
| `phase.note` 警告 | 阶段缺 `phases/<id>.md` | 补文件（或接受空提示） |
| `host file ... does not exist` 警告 | `scenario.host` 指向不存在文件 | 补文件或删掉 `host` 字段 |
| `suggest.waveform ... falls back` 警告 | 引用的波形不存在 | 用包内 id、`builtin:<id>` 或删掉 waveform |
| `waveform.bounds` / `waveform.output` | 频率/强度越界、总时长不是 100ms 倍数、全 0 输出 | 按 §5 边界调整 |
| 导入后版本号没变，担心没生效 | 同 id@version 是覆盖安装，不是失败 | 状态行显示「已导入（覆盖）」；`content/packs/<id>/<version>/` 下的文件已更新，可直接开局 |
| 导入后下拉里显示「（无 active 版本）」且不可选 | 包没有 active 版本，或控制台列表未刷新 | `install-pack --list` 检查 active；重新打开游玩视图 |
| 结束要点很久才变「已结束」 | `aftercareMin` 太大 | 测试包设 `aftercareMin: 0` |
| `waveform.bounds`（name/tags） | segments 波形的 `name` >64 字符、`tags` >8 个或单个 >24 字符 | 缩短 name/tags；或改用 `frames` 写法（不检查这两项） |
| 波形文件没生效、也没警告 | 文件名后缀写成了大写 `.JSON` | 改成小写 `.json`（loader 只扫描小写 `.json`） |
| 有 `waveforms/index.json` 的警告 | 规范 §4.5 的索引文件未实现 schema | 删掉 `index.json`，把每个波形放成独立的 `<id>.json` |
| 模型一直不停某个部位 | 意图表里没有 id 为 `stop` 的意图（scenario 包覆盖了默认表） | 加一个 `{"id":"stop","meaning":"停下"}` 意图；停止必须显式声明 |
| `plannedMinutes` 改了没效果 | 该字段只校验、运行期不读 | 时长在控制台大厅输入；包内只用于声明 |
| 阶段没有推进 | 模型没给 `advanceTo`；或目标不是当前阶段 `next` 的边；或会话时间/`advanceWhen` 条件未满足（模型判断） | 看提示词里的「当前阶段/可推进到/阶段时间窗」；让模型在 `apply_plan` 里给 `advanceTo`（只能取 `next`），非法值会写 `phase_advance` rejected 审计 |

## 10. 与冻结设计稿 `内容包规范.md` 的差异

| 设计稿 | 当前实现 |
|---|---|
| 两段式（导演/写作分离）投影 | 生产是单次调用；`## 导演摘要` 暂未单独使用（拆分模式代码存在但未启用） |
| 阶段图推进 | 已接线：模型在 `apply_plan.advanceTo` 请求推进，引擎按 `next` 校验并写 `phase_advance` 审计；`phaseWindows` 只作提示词事实、不自动切阶段 |
| `corpus.md` 按需检索 | 加载但未注入提示词 |
| `setting.md` 按需检索 | 每回合全文注入（注意长度） |
| `opening` / `npcs` / `secrets` 作为写作素材 | 兼容字段，仅类型校验；不注入 |
| `pack.aftercare.text` 默认收尾文案 | 校验但未消费；`aftercareMin` 生效 |
| 单 `.md` 便捷导入 | 未实现；只接受 zip |
| 界面导入 | 游玩页「开局」卡有「导入内容包」按钮（zip 直传、导入即激活）；**没有**卸载/版本切换按钮（切换走 `--activate`/API；卸载无入口） |
| `waveforms/index.json` | 未定义 schema，会警告并忽略；直接放 `<name>.json` |
| `requires` 各能力 | 只认 `region`、`waveform`，其余警告忽略 |
| `version`（规范只说 semver） | 严格 `x.y.z`；预发布/构建元数据/部分版本都拒绝 |
| `engine`（规范只说 semver 范围） | 只支持 `x.y.z` / `>=x.y.z <a.b.c` / `^` / `~`；不支持 `>`、`<=`、`*`、`||`、预发布 |
| `session` 字段（规范 §3 校验清单未列） | `plannedMinutes`、`phaseWindows`、`aftercareMin` 三个都必需 |
| 「引擎默认 host」/「默认收尾文案」 | 代码里都不存在：host 缺失时提示词没有主持段；`aftercare.text` 从不消费 |
| 每个意图的 `distribution` 缺省 | 代码统一缺省 `synced`；规范写的 per-intent 默认只存在于 freeform 的内置意图表 |
| 区域匹配 | 除「名称/id 完全一致→映射包 id」外，resolver 还有一条别名：**玩家词是包 `label` 的子串**即可命中 |
| 文本编码 / 符号链接 | 运行时不校验 UTF-8（非法字节变替换字符）；zip 导入不检查符号链接/权限位 |
| 波形 `license` 字段 | 静默忽略（loader 不读未知字段） |
