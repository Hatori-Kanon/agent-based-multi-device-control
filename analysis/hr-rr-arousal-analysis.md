# HR / RR（HRV）与性唤起：消费级臂带 + 成人角色扮演场景的可计算研究

> 只读研究，2026-11-01。未改代码、未装依赖、未连设备。范围是生理信号与算法，不含露骨内容。
> 标注：**[文献]** 同行评审/机构文件；**[实测]** 本仓库 HW9 抓包；**[推断]** 由证据推得；**[未验证]** 无可靠来源，需实测。
> 结论先行：**现有文献不支持"用消费级臂带的 HR/HRV 识别性唤起"**。能站住脚的只有"相对个人基线的、与运动/音频/上下文互证的心率趋势"。本文按这个上限设计。

## 0. 结论速览

1. **最强的实验室证据也很弱**：女性看 erotic film 时 SDNN 只降 8.6%（SD 21.7%），HR 只升 1.5%（约 +1.2 bpm，SD 8%）；HRV 曲线模型只解释生殖器唤起方差的 **R²=0.18**，且对**主观**唤起完全不显著 [文献·Lorenz 2012]。
2. 方向是对的：**交感激活不是单纯抑制**，中等升高促进、过高抑制（倒 U 形）[文献·Lorenz 2012；Meston lab]。但这支持的是"群体统计"，不是"个体识别"。
3. **HRV 在个体层面的可判性极低**：超短时（<5 min）HRV 是"代理的代理"，28 项研究里只有 3 项用了严格的 Bland–Altman 一致性标准 [文献·Shaffer 2020]。
4. **光学臂带的 RR ≠ ECG 的 HRV**：PPG 到脉搏波经过 6 步传递函数，体位/运动/温度会改变 PRV 而不改变 HRV [文献·Yuda 2020]。
5. **我们只有 ~1Hz bpm + 手臂静止时的每拍 RR**：60s 够算一个粗 RMSSD，5–15s 只够算 Δbpm（数学约束，不是实现问题）[文献·Task Force 1996；实测]。
6. **HW9 的 RR 门控是"臂动"而非"全身动"**：这修正了旧结论，也意味着 RR 缺失本身就是"手臂在动"的传感器 [实测+推断]。
7. **能做的**：`baselineBpm` + `deltaBpm` + 趋势/斜率 + 质量门控 + 与画面运动/音频/上下文互证 → 输出"事实 + 不确定度"。
8. **不能做的**：识别唤起、区分兴奋/紧张/运动/热、用 HRV 实时判定、把唤起当同意或安全信号。单靠 HR 一律不下结论。
9. **产品含义**：最诚实的定位是"**叙事输入的一条弱证据**"，不是传感器级状态机。提示词只给数字与不确定度，不贴标签。

## 1. 生理学基础与证据
### 1.1 性反应周期里的自主神经变化

| 阶段 | 交感/副交感 | HR / HRV 的典型表现 | 证据强度 |
|---|---|---|---|
| 兴奋（excitement） | 副交感主导生殖器充血，交感同时升高（"双系统共同激活"） | HR 轻升、HRV 轻降；个体差异大于组间均值 | 中（实验室，n≈50）[文献] |
| 平台（plateau） | 交感张力上升，肌张力/呼吸/HR 上升 | HR 可明显高于静息；HRV 下降 | 弱–中（描述性为主）[文献/推断] |
| 高潮（orgasm） | 交感短时爆发，随后副交感回弹 | HR 短时峰值、HRV 短时骤降后回升；持续数十秒 | 弱（多为小样本/自我报告）[推断] |
| 消退（resolution） | 副交感回弹 | HR 下降、HRV 回升（恢复斜率个体差异大） | 弱 [推断] |

要点：**HR 上升既可能来自交感激活，也可能来自副交感撤退**；HRV 下降更偏向交感，但同样受呼吸、体位、运动污染 [文献·Task Force 1996；Kreibig 2010]。因此"HR/HRV 变化 → 性唤起"是**多对一**映射，不可逆推。
### 1.2 指标逐项：哪些有证据、哪些是流行说法

| 指标 | 与性唤起的证据 | 我们的判断 |
|---|---|---|
| **HR（相对基线）** | 实验室均值升 1–2 bpm（被动看片）；真实互动/运动混杂时升幅更大但归因不清 [文献·Lorenz 2012；AHA 2012] | **唯一可用的弱信号**，只能做相对趋势 |
| **SDNN** | 女性看片时 −8.6%（SD 21.7%），倒 U 形解释 VPA 的 R²=0.18 [文献] | 组水平有效，个体噪声大；需 ≥60s 且静息 |
| **RMSSD** | 与 SDNN/pNN50 高度相关（r≈0.42–0.9），主要反映迷走；性唤起研究里少有单独报告 [文献·Task Force/Shaffer] | 可算，但只做 60s 相对变化；不做绝对值 |
| **pNN50** | 与 RMSSD 同向、更粗；Lorenz 中 −12.5%（SD 36.7%）[文献] | 冗余，只作诊断/质控 |
| **HF** | 反映呼吸性窦性心律不齐；需要稳定呼吸 ≥2–5 min | **不做**（窗口不够、呼吸不可控） |
| **LF/HF** | 常被当作"交感/副交感平衡"，但方法学上不成立 [文献·Billman 2013] | **明确不用**，属于流行说法 |
| **样本熵 / ApEn** | 需要 N>200 拍才较稳；短数据对参数极敏感 [文献·Yentes 2013] | **不值得**：60s 只有 60–80 拍，且无性唤起证据 |
| **单次 RR / 逐拍形态** | 无证据；易受异位拍/漏拍污染 | 不用 |
### 1.3 性别差异（必须写进产品假设）

- 主观–生殖器一致性：男性 r=0.66，女性 r=0.26（132 项研究元分析）[文献·Chivers 2010]。这说明**"主观报告"本身就不是可靠真值**，女性尤甚。
- 静息 HRV 低是女性性功能/唤起障碍的**风险因素**（横断面，n=72）[文献·Stanton 2015]；性唤起过程中 RSA 在功能/障碍组间有差异（n=84, p=.02）[文献·Stanton 2017]。这是**特质/组间**证据，不能拿来做**状态**判定。
- 男性 HR/HRV 与唤起的直接研究更少，多数依赖阴茎体积描记 [推断]。**不要假设"男性 HR 反应更强所以更好测"** [未验证]。

## 2. 测量与伪影

- **PPG vs ECG**：ECG 测电活动，PPG 测血流容积；PPG 对接触压力、肤色、灌注、体动更敏感，且脉搏波传导会引入额外变异 [文献·Yuda 2020]。静息、贴合良好时 PRV 可近似 HRV；运动/ vasoconstriction 时不成立 [推断，与文献一致]。
- **运动伪影**：手臂摆动、握持、翻身都会造成基线漂移与漏拍。HW9 的对策是**直接关掉 RR**（见 §8），所以"没有 RR"不等于"设备坏了" [实测]。
- **接触/灌注**：接触不良 → 信号幅度下降 → HR 跳变/掉零；交感激活导致外周血管收缩时，PPG 幅度也会下降 [推断]。HW9 的 bit1/bit2 恒 0，只能用 `HR=0` 判摘下（延迟 ≤1.1s）[实测]。
- **呼吸/说话/体位/温度/咖啡因/时段**：均改变 HR 与 HRV，且与性唤起无关。文献对 HRV 的这些混淆因素有共识，但**没有**任何一项能在我们的场景里被可靠测量或扣除 [文献·Task Force；推断]。
- **超短时 HRV 的边界**：5 min 是短时标准；60s 可用于部分时域指标的粗估；30s 边缘；10s 基本不可用 [文献·Shaffer 2020]。我们的 **5–15s 窗口只做 Δbpm**，不做 RMSSD——这是数学约束（5–15 拍）。
- **1Hz + 无时间戳的重建误差**：把每包 RR 累加反推拍时刻，绝对时刻带 0–200ms 系统偏移、±100ms 级抖动（实测通知间隔 0.90–1.13s）[实测+推断]。对 1s 分辨率窗口与 5–15s 事件对齐**够用**；对 ms 级跨设备对齐**不够**。
- **重要澄清**：RMSSD/SDNN 只用 RR 数值与顺序，**不需要拍时间戳**；时间戳只用于开窗、断档检测与事件对齐。不要把"时间重建误差"误当成"HRV 算不准"。
- **设备端平滑**：HW9 的 bpm 是设备算的（RR 中位反推 769ms vs 实测 747ms，比值 0.971），说明 bpm 不是瞬时值而是窗口平滑结果 [实测]。**<3 bpm 的 ΔHR 可能只是平滑伪影** [推断]。
- **断档**：4.4% 的包只有 HR 无 RR（flags=0x00），且断线期间数据按规范必须丢弃 [实测/标准]。任何跨断档的逐拍差分都要作废。

## 3. 可计算信号（以我们实际能拿到的数据为准）
### 3.1 数据形态

- `bpm`：~1Hz，设备平滑，连续可用（运动中也有）。
- `rrMs[]`：手臂静止时每拍一个，约 1 包/秒；覆盖率 ~97%；运动中为 0。
- 可能断档：断线、摘下（HR=0）、HR-only 包。
### 3.2 特征清单（按性价比排序）

| 特征 | 定义 | 窗口 | 可用条件 | 价值 |
|---|---|---|---|---|
| `baselineBpm` | 静息期 bpm 中位数 | 5–10 min 校准，或滚动 5 min 低运动 | 运动低、无动作 | 必需 |
| `deltaBpm` | `EMA_fast(bpm) − baselineBpm` | fast τ≈5s | 始终 | **主信号**；`deltaBpm/baselineBpm` 即百分比，但跨人不可比 |
| `slopeBpmPerMin` | 30s OLS 斜率 | 30s | 始终 | 趋势/加速度 |
| `hrZ` | `(EMA − med)/1.4826·MAD`（会话内） | 滚动 10 min | 有基线 | 归一化 |
| `rmssd60` | `sqrt(mean(ΔRR²))` | 60s | RR 覆盖 ≥90%、伪影 <10%、静息 | 低频状态 |
| `rmssdRatio` | `ln(rmssd60 / rmssdRef)` | 60s vs 基线 | 同上 | **唯一建议的 HRV 用法** |
| `pNN50_60` | 相邻 RR 差>50ms 占比 | 60s | 同上 | 质控/诊断，不进模型 |
| `rrCoverage60` | 实收拍数 / 应有拍数 | 60s | — | 质量门控 |
| `artifactRatio` | 相邻 RR 变化>20% 的比例；辅以 RR 中位/IQR | 60s | — | 质量门控/伪影检测 |
| 样本熵 | — | ≥200 拍 | — | **不做**（§1.2） |
### 3.3 窗口、滞后、平滑

- **基线**：开场 5–10 min 静息校准最好；不现实时用"最近 5 min 低运动段"滚动更新，动作发生时**冻结**基线 [推断/设计]。
- **反应窗口**：动作后 **5–15s**；基线取 `[actionAt−30s, actionAt]`。1.5–3s 只适用于运动/音频，套到 HR 会系统性判"无反应" [推断，与设计草案一致]。
- **滞后**：情绪/中枢性 HR 反应通常在数秒内起效、10–30s 达峰 [推断]；性唤起的真实滞后未知 [未验证]。离线验证时要搜索 0–40s 的滞后互相关。
- **平滑**：EMA 快 τ≈5s + 慢 τ≈60s；状态机用 dwell time（≥15s）防 1Hz 抖动。CUSUM 可用于"持续偏移"检测，但会引入额外滞后，MVP 不做 [推断]。
- **不可计算**：RR 缺失/覆盖 <80%、伪影 >20%、`HR=0`、运动中、基线未建立、会话 <3 min、多源冲突。此时输出 `quality` 事实 + `ambiguous`，**不猜**。

## 4. 唤起代理分数（arousal proxy）设计草案
### 4.1 设计原则

1. **可标定**：先验权重是占位，最终由带标签数据拟合；没有标签时**只输出趋势，不输出"唤起等级"**。
2. **多模态互证**：HR、RR-HRV、画面运动/音频、上下文四路；运动只做**归因门控**（动了就不能把 HR 上升算作唤起），不做正向证据。
3. **单靠 HR 不下结论**：HR 单独最多输出"心率高于基线 N bpm，原因不确定"。
4. **宁可不确定**：误报"高唤起"的代价（错误加码/越界感）远大于漏报。
### 4.2 特征 → 归一化 → 分数

```
e_hr   = clamp( (hrFast − base) / (2.5·baseSd), −1, +1 )
e_hrv  = clamp( (ln(rmssdRef) − ln(rmssd60)) / (2.5·refSdLog), −1, +1 )   // 仅 RR 可用
e_mot  = clamp( (motionEnergy − motBase) / (2.5·motSd), −1, +1 )          // 画面/音频
e_ctx  = +0.4 若动作后 ≤20s、运动低、亲密类动作；否则 0
S      = 0.55·e_hr + 0.25·e_hrv + 0.20·e_ctx        // 先验权重，待标定
level  = (S + 1) / 2                                 // 0–1
```

> **Lead 复核备注（2026-11-01）**：上式里的 `level=(S+1)/2` 与 §4.3 状态机阈值**不自洽**——中性（S=0）时 level=0.5，会立刻落进 `plateau`（≥0.50）。整合到产品时改为**正值证据加权**：`level = 0.55·max(0,e_hr) + 0.25·max(0,e_hrv) + 0.20·e_ctx`，阈值 0.25/0.50/0.70 才成立。修正版见 `感知闭环与控制分离-设计草案.md` 附录 B。

**互证与门控**：`e_mot` 只做归因门控——运动/音频高 → `e_ctx=0`、confidence 降档，**不把"在动"当成"唤起"**。允许 `level>0.6` 的条件：`e_hr` 与 `e_hrv` 同向（HRV 可用时）；HRV 不可用时需"HR 上升 + 动作后确有反应（运动/音频）"；只有 HR 一路 → `level≤0.55`。
### 4.3 状态机

```
baseline  → level<0.25 且 |slope|<1 bpm/min，持续 ≥30s
rising    → level≥0.25 且 slope>+1 bpm/min，持续 ≥10s
plateau   → level≥0.50 且 |slope|<1，持续 ≥15s
high      → level≥0.70 且 (e_hrv<−0.3 或 运动/音频同向)，持续 ≥10s
recovery  → 从峰值回落 ≥0.20，或 slope<−1 持续 ≥20s
ambiguous → 质量差 / 互证失败 / 已知混淆（刚运动、热、咖啡因、情绪事件）
```

进入/退出阈值不同（滞回），`high` 需更严；`ambiguous` 可随时覆盖其它状态。
### 4.4 置信度

```
q = min(1, rrCoverage/0.9) · (1−artifactRatio) · contactOk · freshnessOk
a = 1 − |e_hr − e_hrv| / 2            // HRV 不可用时 a=0.6
c = clamp(0.35 + 0.65·q·a·(nSessions/20), 0, 0.95)
```

上限约束：无 RR → c≤0.50；运动高 → c≤0.30；基线未建立 → c≤0.25。`nSessions` 是已标注会话数，**没有标签就不该有高置信度**。
### 4.5 阈值来源

| 参数 | 初值 | 来源 |
|---|---|---|
| 基线时长 | 5–10 min | [文献] 短时 HRV 标准 5 min；经验上加倍更稳 |
| ΔHR 进入阈值 | 5 bpm | [推断] Lorenz 的组均值仅 +1.2 bpm、SD 8%，5 bpm≈0.6 SD；**必须标定** |
| `hrZ` 阈值 | 1.5 | [推断] 经验值，需按人校准 |
| RMSSD 变化 | −15% | [推断] Lorenz SDNN −8.6%±21.7%，−15% 仍在 1 SD 内，单窗口不可靠 |
| 伪影阈值 | 相邻 RR 变化>20% | [社区/惯例] Kubios/Malik 风格；原文未核 [未验证] |
| 覆盖率下限 | 80–90% | [推断] 低于此 RMSSD 偏差不可控 |
| dwell time | 10–30s | [推断] 对抗 1Hz 噪声与设备平滑 |
| 运动阈值 | 见设计草案（Δ运动 0.08 等） | 来自现有 `ReactionProbe`，需摄像头侧标定 |

> 所有权重与阈值都应存为**带版本号的配置**，UI 可调、审计可查；默认值不是"科学结论"。

## 5. 个人化与验证
### 5.1 标签怎么收（不打扰是硬约束）

- **0–10 自报**：UI 一个大滑块，60s 一次可选，一键提交；不打断叙事。
- **事件标记**：开始/暂停/峰值/结束/事后照顾，一键打点；时间戳对齐到 1s。
- **分段标签**：事后回看时间轴，给 30–60s 段打 0–10 或"高/中/低"；比实时更可靠。
- **禁止**把"实验室生殖器测量"当家庭真值：VPA 与主观报告的一致性只有 r=0.26（女）/0.66（男）[文献·Chivers 2010]，且 VPA 女性本人不可感知。
### 5.2 离线评估

- **相关**：会话内 Spearman（proxy vs 自报），并做 0–40s 滞后扫描取最大。
- **分类**：自报 ≥7 vs ≤4 的 AUC；同时报**校准曲线**与 Brier score（概率是否可信比 AUC 更重要）。
- **分层**：按会话/被试分组交叉验证（GroupKFold），禁止随机按样本切分（自相关泄漏）。
- **基线对照**：用"只有 ΔHR"与"ΔHR+HRV+上下文"对比，证明多模态是否真的加分；加不过就不加。
- **显著性**：置换检验 + 置信区间；报告"没有显著优于基线"也算结果。
### 5.3 需要多少数据、怎么防过拟合

- 粗算：检测 r=0.4 需 ~47 个独立点；但生理序列自相关会把有效样本降到 1/5–1/10 → 实际需要**数百个 30–60s 段**。
- 现实做法：**≥10 次会话 × 每次 ≥20 个标签段**作为 pilot；在此之前只用手工先验权重，不训练。
- 防过拟合：特征 ≤4 个、L2 正则、固定超参、嵌套 CV、按会话留出；**不做**每人一套阈值（除非该人另有 ≥5 次留出会话）。
- 明确区分：**pilot 的相关性** ≠ 可用产品；先证明"比常数基线好"，再谈阈值。

## 6. 工程落地建议
### 6.1 数据契约（扩展现有 `SensorSource`，`kind` 新增 `hr`）

```jsonc
{
  "sourceId": "hr-arm-1", "kind": "hr", "ts": 1790000000000,
  "bpm": 78, "rrMs": [812, 806], "contact": "yes",
  "quality": "rr-rest-only",        // rr | rr-rest-only | no-rr | warming | poor-contact | stale | reconnecting
  "baselineBpm": 72, "deltaBpm15s": 6, "slopeBpmPerMin30s": 2.1,
  "rmssd60": 20.4, "rmssdRatio": 0.02, "rrCoverage60": 0.97, "artifactRatio": 0.0,
  "armStillRatio60": 0.93,          // RR 出现率，作为"臂静"证据（非全身静）
  "arousalProxy": { "level": 0.42, "confidence": 0.55, "state": "rising", "reasons": ["hr_up", "hrv_unavailable"] },
  "modelVersion": "proxy-0.1"
}
```

- 保持 `latest()`/`freshnessMs()` 不变；`kind` 联合类型加 `'hr'`，`SensorRegistry` 不假设图像。
- `arousalProxy` 只在**有基线且质量合格**时出现；否则字段缺省，提示词少一行，而不是给 0。
### 6.2 计算放哪

- **core（在线）**：环形缓冲 + 1Hz 特征（纯 TS、无平台 API）；`baseline/delta/slope/rmssd/quality/proxy` 全部在 core，O(1) 滚动，1Hz 开销可忽略。
- **离线（analysis）**：权重拟合、滞后扫描、AUC/校准、伪影阈值调参；产物是一个 JSON 配置，不把训练代码塞进 core。
- **缓冲**：bpm 600 点（10 min）、RR 90s（~90 拍）、特征 120 点；断档即清 RR 缓冲并置 `warming`。
- **频率**：快照 1Hz；proxy 0.5Hz；提示词每回合一条（≤200 字）。
- **性能**：RMSSD 每次重算 ~80 拍，1Hz 下微不足道；避免热路径分配（TypedArray）。
- **隐私**：**原始 RR 默认不落盘**，只在内存；审计只记聚合值（`bpmDelta`、`artifactRatio`、`quality`）；调试落盘需显式开关 + 固定路径 + 一键删除；不接厂商云。

## 7. 伦理与产品边界

- **唤起 ≠ 同意**：生理反应不表达意愿、不能撤销、不能替代口头确认；不得据此自动加码、自动解锁、跳过确认。
- **不进安全路径**：`arousalProxy` 不是 `SafetyPolicy` 的输入，也不参与急停判定；急停永远是人类带外按钮。
- **误判代价不对称**：假阳性（把紧张/运动判成"想要"）可能导致越界，代价远高于假阴性。所以默认 `ambiguous`，阈值偏保守。
- **不宣称医疗/心理诊断**：不输出"焦虑/抑郁/性功能障碍"判断；不做健康建议。
- **成人内容合规**：成年人、自愿、本地优先、最小化采集；不把生理数据用于画像/推荐/广告。
- **提示词措辞**：只给事实 + 不确定度，不贴标签。例：
  - ✅「心率 78，比基线高 6；RR 不可用（手臂在动）；可能是运动/热/紧张，不确定。」
  - ❌「ta 很兴奋」「快高潮了」「身体很诚实」。

## 8. 直接回答：HW9 的"臂动门控"意味着什么

- **修正成立**：RR 的开关由**臂带自身运动传感器**触发，不是"全身运动"。这与我们的抓包一致：走动 2 min 时 RR=0（手臂在摆），单纯抬臂时 RR 仅 6.4%，而静息 96.7% [实测]。旧结论"运动关 RR"应改写成"**臂动关 RR**" [实测+推断]。
- **佩戴位置**：非惯用臂、前臂上段（肘下 2–3 指）、贴合但不勒；不要戴在腕部（腕部活动更多）。手臂放在床面/扶手上，避免悬空 [推断]。
- **动作设计**：内容层少设计挥臂/支撑/抓握类动作；多用躯干、髋、腿的动作；需要手臂动作时，预期 10–30s 的 RR 空洞 [推断]。
- **"手臂静止但身体在动"时 RR 可信吗？** **可能仍会输出，但不能默认可信** [推断]。理由：设备只看到手臂静止；PPG 仍受静脉回流、外周 vasoconstriction、出汗、接触变化影响；且此时 HR 本身被体动抬高，归因更差。判据：`rrCoverage`、`artifactRatio`、`RR 中位 vs 60/bpm` 一致性；任一异常 → `quality=rr-suspect`，proxy 降级。
- **降级阶梯**：`rr`（静息、质量好）→ `rr-rest-only`（默认）→ `no-rr`（只有 bpm，禁 HRV）→ `stale`（断线）。每级对应不同的 confidence 上限（§4.4）。
- **不要用 `rrAvailable` 同时做"质量"和"臂静"两个用途而不声明**：它是行为相关的（用户不动才有），存在选择偏差——最"投入"的时候可能恰好没有 RR。

## 9. 风险与未知

1. **最根本的风险**：把"相对 HR 趋势"包装成"唤起识别"，用户与模型都会过度信任；这是产品伦理问题，不是算法问题。
2. **选择偏差**：RR 只在臂静时可用，而臂静与"投入程度"相关 → 训练/评估样本非随机。
3. **设备 bpm 平滑**：未知窗口与算法，可能抹掉 5–15s 的真实反应；ΔHR 分辨率可能只有 ±2–3 bpm [未验证]。
4. **个体差异**：静息 HR、HRV、反应幅度差异极大；跨人阈值不可移植 [文献+推断]。
5. **混淆与标签**：热/咖啡因/酒精/药物/睡眠/情绪/疼痛都与唤起同向且不可测；自报标签受回忆与社会期望影响，家庭场景没有"金标准"。
6. **PPG 在高唤起时可能变差**：外周血管收缩/出汗 → 信号幅度下降，恰好在最需要时最不可靠 [推断/未验证]。
7. **多设备串行选设备**：与郊狼共用隐藏 worker，重连可能抢占；需串行队列（既有结论）。
8. **未知**：性唤起特异的 HR 滞后与幅度（无家庭场景数据）；女性/男性差异在我们的设备上是否可测；60s RMSSD 在真实互动中的重测信度。
