# 前端界面重做（v2「墨金」）— 实施与验收记录

> 起因：用户反馈「前端 UI 也太丑了，我都没有玩的欲望」，要求参考 `ai-for-coyote` 项目重做一版。
> 范围：控制台（`index.html` + `app.js`）、游玩页（`play.html` + `play.js`）、手机急停页（`phone.html`）、
> Electron 设备运行时窗口（`src/renderer/index.html`），以及新增的共用设计系统 `src/ui/style.css`。
> 设计说明与类名约定见仓库根目录 [`前端界面设计.md`](../前端界面设计.md)。

## 1. 原问题

改造前的页面是「调试表单」式布局：内联 CSS、统一灰蓝、没有层级、没有视觉重心。游玩页一屏里是
「内容包下拉 + 会话上限滑条 + 状态 dl + 设备部位输入框」，没有任何「在玩」的感觉；没有内容包时
整页几乎空白。基线截图（本地 `.ui-shots/baseline-*.png`，不入库）：

| 页面 | 改造前 |
| --- | --- |
| 控制台 | 裸标题 + 灰卡片堆叠，通道条只有细蓝进度；1600×1000 下大片空白 |
| 游玩页 | 顶栏一个「开始」工具条，下面全是表单；无内容包时整页几乎空白 |
| 手机急停 | 一行按钮的小页面 |

## 2. 做了什么

### 2.1 设计系统（新增 `src/ui/style.css`，约 1900 行）

- 令牌化：`--ink / --panel / --gold / --text / --line / --r-*` 等，四个界面共享同一套值。
- 参考 ai-for-coyote 的「近黑 + 金」语言：细描边圆角卡片、金色药丸、金色滑杆、系统字体栈
  （不引外链字体，CSP 仍是 `default-src 'none'`）。
- 组件：`.topbar/.brand/.nav/.card/.btn/.pill/.tag/.life/.meter/.stats/.device/.ch/.wf-card/`
  以及游玩页专用的 `.lobby/.stage/.now-card/.bubble/.choice/.composer/.rail`。
- 动效克制（入场只做位移、长按急停进度条）；`prefers-reduced-motion` 全关。
- 窄屏回退：1240px 收窄栏宽；980px 单列 + 顶栏/底栏/输入框吸附，急停在滚动时仍在视口内。

### 2.2 控制台

- 三栏驾驶舱：左栏设备管理/感知/运行状态，中栏设备卡 + 波形库，右栏审计/日志/调试（默认收起，入口卡）。
- 顶栏：品牌 + 日志/审计/调试 nav（激活金色）+ 状态药丸 + 游玩入口 + 常驻急停。
- 通道条：强度进度条是每行视觉焦点，上限滑杆带金色进度（`--fill`），当前输出显示为带标签的 tag。
- 添加设备改为真正的对话框（Esc/点背景关闭，焦点进出）。

### 2.3 游玩页

- **大厅**：海报式开场（`EMBODIED ROLEPLAY` + 衬线大标题 + 副标题），左「开局」卡
  （内容包/时长/会话上限/开局 CTA），右「准备工作」三步；无内容包时下拉显示明确占位而不是空白。
- **舞台**：内容列限宽 1040px；「现在」eyebrow + 大字衬线台词（clamp 20–25px）+ 对话流气泡
  （旁白/你/系统分隔）+ 序号选项卡 + 底部输入框；右轨只放「状态/内容包/边界」「连接与部位」「感知」。
- 结束态是安静的收尾卡（不再保留金色大字框和倒计时），暂停/锁定沿用顶栏药丸与红色横幅。
- 底栏：暂停/继续/结束 + 长按空格急停；急停按钮常驻顶栏。

### 2.4 手机急停 / Electron 窗口

- 手机页改为「红色圆钮 + 状态药丸 + 带外通道说明 + token 卡」的应急面板；协议与行为不变。
- Electron 设备运行时窗口换成同一色系（内联同令牌），结构与 `renderer.js` 生成类名保持不变。

## 3. 审查与修复

实现是三个子代理并行做的（游玩页 / 控制台 / 手机页+本地预览服务），Lead 负责设计系统、集成与收紧。
随后**两个独立只读审查子代理并行**逐项验收，报告在
[`ui-review-play.md`](ui-review-play.md)（视觉，4 阻塞 + 9 应修）与
[`ui-review-code.md`](ui-review-code.md)（代码/契约，4 阻塞 + 10 应修）。

第一轮修复完成后，又由第三个只读复核子代理逐条复核（[`ui-review-fixes.md`](ui-review-fixes.md)）：
原始 8 个阻塞的故障全部解除，但修复本身暴露了 3 个新问题，已全部修掉并复测：

- 乐观回显在请求失败时会伪造历史并吞掉草稿 → 增加 `rollbackPlayerEcho`（删气泡、还原 pending、恢复草稿），
  实测失败前后气泡数不变、草稿仍在；
- 控制台把「按钮聚焦」也算成编辑，导致设备卡停止刷新 → 只有表单控件聚焦才跳过重建，
  同时按「第几张卡 + 按钮文字」在重建后把焦点放回等价按钮（实测重建后焦点仍在「试跑 15s」）；
- `#sessionState` 虽然是 aria-live，但每 500ms 无条件重写文字 → 加变化守卫，实测 2.6s 内 0 次 mutation。

## 5. 已知遗留（不阻塞）

1. **字号阶梯仍偏密**（10.5/11/11.5/12/12.5/13/13.5…）：视觉审查建议收敛成 5 档，属于纯打磨，未做。
2. **底栏主控**没有参考项目那种居中悬浮圆形按钮：暂停/继续/结束仍是普通按钮（急停在顶栏更醒目）。
3. **游玩页「部位」仍是输入框**，只是默认做成无边框、聚焦才显出可编辑；chip + 点击编辑的形态没做。
4. **控制台的导入/试跑/存入库没有 in-flight 锁**：快速双击会重复 POST（急停本身幂等）。
5. **会话上限默认 100%**：大厅滑杆默认值会随每次开局写入；如果上一局调低过，重开页面后默认回到 100%。
   这是沿用服务端 `ceilingPercent` 缺省语义，语义上仍是「只有人类能写」，但多局之间不做记忆。
6. `src/renderer/index.html`（设备运行时窗口）目前没有被主进程加载（主窗口加载的是 dashboard `/`），
   本次只是把它同步成同一色系，未接线。
7. `手机页` 仍用 `localStorage` 缓存 token（改造前行为），只是加了 try/catch。
